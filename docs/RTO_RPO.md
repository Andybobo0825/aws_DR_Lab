# RTO / RPO 定義

## 定義

- **RTO（Recovery Time Objective）**：從事故發生到服務恢復可用的目標時間。
- **RPO（Recovery Point Objective）**：可以接受的最大資料遺失時間點。

## 本專案預設值

### 無 CRR

- **RTO**：目標 15 分鐘內完成手動切換演練。
- **RPO**：取決於最後一次手動同步時間，演練時需明確記錄。

### 有 CRR

- **RTO**：目標仍以 15 分鐘作為演練基準，實際切換時間視 DNS / 流量切換方式而定。
- **RPO**：接近 S3 replication delay，通常為分鐘級，但仍需依實測結果回報。

## 為什麼這樣設計

- 這是一個 **作品集 DR lab**，不是高成本 production service。
- 預設路徑必須易於 destroy 與重建。
- 只有在需要展示更完整 DR 能力時，才打開 CRR 或 DNS 切換。

## 如何驗證

- 對 primary 做內容更新。
- 觀察 DR 是否同步（CRR 開啟時）。
- 人工切換網站入口到 DR。
- 記錄從故障發生到服務恢復的分鐘數。
- 記錄最後一次可接受資料點。

## 報告建議

每次演練都應該回填：

- 事故開始時間
- 偵測時間
- 切換開始時間
- 切換完成時間
- 實際 RTO
- 實際 RPO
- 改善項目
